**borrowing**

> **A borrowed parameter is not consumed by the callee. Ownership stays with the caller (outside).** The callee (that insides of called function) may read it but must not `dec` it (to not destroy by inadvertedly) (and the caller must not `inc` !!! before passing). Whoever *owns* it is responsible for the eventual `dec`.

```
@& in source  →  markBorrowed / isMarkedBorrowed (BorrowedAnnotation.lean)
              →  Param.borrow : Bool          (LCNF/Basic.lean:68)
              →  InferBorrow / PropagateBorrow (infer more borrows automatically)
              →  ExplicitRC.lean              ← THE pass that skips inc/dec
              →  EmitC.lean_ / EmitRust.lean  ← dumb printers
```

`BorrowedAnnotation.lean` is trivial — just tags an `Expr`:
```lean
def markBorrowed   (e : Expr) : Expr := mkAnnotation `borrowed e
def isMarkedBorrowed (e : Expr) : Bool := annotation? `borrowed e |>.isSome
```
which becomes the `borrow` field on the parameter (`LCNF/Basic.lean:68`, and `IR/Basic.lean:210`). The IR pretty-printer shows it as `@&`:
```lean
-- src/Lean/Compiler/IR/Format.lean:85

```

## 3. Where borrow actually does its work — `ExplicitRC`, not the emitter

This is the key insight: **borrow is entirely resolved during RC insertion.** By emit time the `inc`/`dec` are already explicit `FnBody` nodes; the emitters just print whatever nodes exist.

`ExplicitRC.lean` marks borrowed params as "borrowed values" and then never inserts a `dec` for them:

```lean
-- src/Lean/Compiler/LCNF/ExplicitRC.lean:100
def visitParam (p : Param .impure) : M Unit := do
  addDerivedValue #[] p.fvarId
  if p.borrow && p.type.isPossibleRef then
    addBorrowedValue p.fvarId          -- ← this value will never be dec'd
```

The header comment spells out the whole point (`ExplicitRC.lean:22-26`): borrowed params *"avoid performing the majority of reference counting"*, plus **derived borrows** — anything projected out of a borrowed value is itself treated as borrowed (safe, because a borrowed value won't be mutated/freed under you). Live-variable tracking even keeps a dedicated `borrows` set that *"can thus never be freed"* !!!!! (`ExplicitRC.lean:185`).

Correspondingly, when an argument lands in a *borrowed* parameter slot, no `inc` is inserted (e.g. `FloatLetIn.lean:152` gates on `sig.params[i]?.any (·.borrow)`).

## 4. The C++ runtime side (`origin-master-src`) — pure documentation

On the runtime side the borrow convention is only a **documenting typedef** — all four are literally `lean_object *`:

```c
/* origin-master-src/include/lean/lean.h:175-180 */
/* The following typedef's are used to document the calling convention for the primitives. */
typedef lean_object * lean_obj_arg;   /* Standard (owned) object argument. */
typedef lean_object * b_lean_obj_arg; /* Borrowed object argument.        */
typedef lean_object * u_lean_obj_arg; /* Unique (non-shared) argument.    */
typedef lean_object * lean_obj_res;   /* Standard object result.          */
typedef lean_object * b_lean_obj_res; /* Borrowed object result.          */
```

This is exactly your `lean_string_append(lean_obj_arg s1, b_lean_obj_arg s2)` example: `s1` is owned → the function `dec_ref(s1)`s it internally; `s2` is borrowed → the function *never* touches its refcount, the caller keeps it. The `@&` on the Lean-side signature of that extern is what tells `ExplicitRC` "don't you dare emit a dec for arg 2 — the C code isn't expecting to own it."

## 5. EmitC vs EmitRust — both are "dumb," and neither changes the *type*

```lean
-- src/Lean/Compiler/LCNF/EmitRust.lean:35
def leanObjectPtrTy : String := s!"*mut {leanObjectTy}"   -- = *mut lean_object
-- toRustType, line 49:
| object => leanObjectPtrTy    -- borrowed or owned → identical Rust type
```
No `&T`, no lifetime — just a raw pointer, matching C's ABI.

The inc/dec themselves are emitted identically to C, straight from the RC nodes:
```lean
-- src/Lean/Compiler/LCNF/EmitRust.lean:996
| .inc fvarId n check persistent k =>
    unless persistent do emitInc fvarId n check   -- → lean_inc / lean_inc_ref
| .dec fvarId n check persistent objs? k =>
    unless persistent do emitDec fvarId n check objs?  -- → lean_dec / lean_dec_ref
```
